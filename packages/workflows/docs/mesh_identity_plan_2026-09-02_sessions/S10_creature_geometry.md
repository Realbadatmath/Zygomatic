# S10: creature geometry generation and rigging. Pixal3D, SAM 3D Objects, UniRig, the nulls

Read `README.md` first. Plan section 4 (Creatures), section 7 Phase 3, section 12. Notes: `research_reconstructors.md` (whole), `understand_props_recon.md` section 1 and 3, `research_process.md` Q2.

## Why this session exists
A single-image reconstructor invents the unseen half: TRELLIS.2-4B from the pufferball's front cell produced a mesh whose side-view radial extent is 49 percent further from the anchor than a featureless sphere, with the tail absent as geometry (`lora-datasets/creatures/d0e44ab002ad/mesh_trellis/`). We hold, per creature, a front anchor and a right-side anchor (`lora-datasets/creatures/d0e44ab002ad/locks/full_body_J_cand_1.png` and `locks/side_S_cand_2.png`), a body-plan sentence in `brief.json`, and a klein LoRA. The capability that matters is POSED multi-view conditioning. Pixal3D (TencentARC) has it (`inference_mv.py --views_dir` with `transforms.json`; shipped rig four views at 0, 90, 180, 270 degrees, elevation 0, 20 degree FOV, first frame the canonical front; `--num_views 2`). Its licence checked at file level on 2026-09-02: LICENSE plain MIT, NOTICE lists only dinov2 (Apache), TRELLIS.2, Direct3D-S2 and MoGe (MIT), README clean, HF repo NOT gated, BUT the card metadata carries `extra_gated_eu_disallowed: true`. That flag is inert while gating is off and is a statement of intent.

## Tasks
1. **Pixal3D, licence first.** Clone `github.com/TencentARC/Pixal3D` (default branch `master`); re-run the file-level check on the clone: `grep -rniE "EUROPEAN UNION|Territory|non-commercial|Hunyuan" --include=*.py --include=*.txt --include=*.md .` must be empty; read NOTICE. Download the weights from `huggingface.co/TencentARC/Pixal3D` (the `*_mv` checkpoints are the multi-view set) and pin sha256 of every file; write a `model_licences_pending/S10.json` entry (MIT, source URLs, verified date) whose note records the `extra_gated_eu_disallowed` metadata as an OPEN QUESTION and the instruction to re-read the card before any re-download. Install per the README on a copy of the TRELLIS.2 venv: `requirements.txt`, `natten==0.21.0` built for sm_89 (`NATTEN_CUDA_ARCH=8.9`), the `utils3d` wheel the README links. Check whether inference imports nvdiffrast; if the texture stage needs it, use the geometry stage only and say so.
2. **Run it against the nulls.** Views dir: frame 0 the front anchor, frame 1 the side anchor at azimuth 90 (right profile; use the shipped `transforms.json` and `--num_views 2`; alpha channels from `bg_remove_service` or BiRefNet as TRELLIS did); `--low_vram` if needed. Arms: MV (front plus side), N0 front-only same seed (compare with the existing TRELLIS.2 mesh too), N1 front plus a horizontally MIRRORED front in the side slot (does the second view carry information, or only tokens). Metrics: radial-extent profile at the side yaw from `pbmetrics` (1.0 equals as wrong as the sphere; canon procedural 0.641, TRELLIS 1.493), DINOv2 view-rank of the true view among 16 renders (chance 8.5), and the binary checks the anchors demand: tail present, mouth present. Ledger per arm.
3. **SAM 3D Objects** (Meta, SAM License, the same family accepted for SAM 3 and SAM 3D Body; contracting entity Meta Platforms Ireland for EEA users). Own venv per `requirements.inference.txt` (kaolin 0.17, gsplat). File-level check: kaolin is Apache-2.0 at root but ships `kaolin/non_commercial/` (FlexiCubes) under an NVIDIA licence; never import it, and grep the SAM 3D Objects code for it. Single-view first, then a community multi-view fork (the training-free multidiffusion one, not the Depth Anything 3 one). Same arms and metrics as task 2.
4. **UniRig** (MIT code and weights, `github.com/VAST-AI-Research/UniRig`, `huggingface.co/VAST-AI/UniRig`): own Python 3.11 venv; rig the solid procedural pufferball GLB and the best generated mesh; null: a hand-placed armature with Blender automatic weights; score deformation artefact area at a fixed tail bend and a fixed leg bend; export rigged GLB to `mesh_rigged/`.
5. **Deform to anchors.** If a generated mesh has the tail but wrong proportions, shrinkwrap or lattice the procedural mesh's silhouette at the two anchor yaws in Blender and report the silhouette IoU change against N0. The anchors are the reference, never the generator.

GATES: every geometry claim reported against N0 AND N1; licence receipts (sha256 pins, entries appended); UniRig against its null.
