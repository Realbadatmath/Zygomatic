## 2. `t5_phalanx_ratio` — the root cause, with file and line

### What the defect is

`geom/form/hands.py:2050 skeleton()` and `geom/mesh_skeletons.py:621 _build_mesh()` are
two doors onto one cage, and both compose the correction through
`geom/anthro/hand_correction.py:308 effective_scales(phenotype, local_changes,
bone_scales, params)`. That function's `params` argument is a **three-state signal**
(documented at `hand_correction.py:310-327`):

| `params` | meaning | what it does |
|---|---|---|
| `None` | a fresh build, no registered body behind it | **SOLVE** a new correction |
| carries `hand_correction` | issued *with* the correction | reuse the RECORDED scales verbatim |
| present, no `hand_correction` | issued *before* the correction existed | apply **nothing** |

Reach either door with `params=None` for a body that *has* a record and it silently takes
the fresh-build branch: it re-solves a correction from the phenotype instead of reusing
the one the body shipped with. That is the split-brain — a right number about the wrong
body.

### Where it is NOT

`geom/anthro/gates.py:4844 _p_hands` → `hands.py:2892 check_digits` threads `params`
correctly, and `gates.py:4839-4843` carries a comment naming this exact failure mode.
Both doors were verified to return the same effective scales for the same recipe on all
four registered bodies (`one door: yes`, below). **The gate path is sound.**

### Where it still WAS — and is now closed

`geom/form/hands.py:1080-1086` (`check_hand_mesh`) unlocked the three digit predicates
from a params dict and then called all three **without forwarding `params`**:

```python
preds['digit_chains']  = check_digit_chains(phen, loc, bs, F['side'])
preds['phalanx_ratio'] = check_phalanx_ratio(phen, loc, bs, F['side'], v, faces)
preds['child_hand']    = check_child_hand(phen, loc, bs, F['side'],
                                          params.get('anatomy_layer'))
```

All three signatures accept `params=`; this one door did not pass it. On today's roster
the omission is invisible (a body issued under the current solver re-solves to within
~1e-14 of its record), and it becomes a silent lie the moment the solver, the library or
the recorded version moves. `check_hand_mesh` has **no callers outside its own module**
today — grep across the repo returns only `hands.py:3396` and `hands.py:3423`, both in its
own CLI/self-test — so this was a latent hazard, not a live one. Fixed: all three calls
now thread `params=params`, with the reasoning and the measured before/after in the
comment above them.

### The self-test the brief asked for

## 3. `t1_build_target_stature` — what actually blocks it

The gate reads `params['height_target_m']` and reports MISSING without one.

- `build_originals()` (`mesh_skeletons.py:2553`) has always recorded it — **female 1.68,
  male 1.85 both run the gate and PASS.**
- `derive()` records it only when the caller passes `target_height_m=`, and **abel and
  cornelis were derived without it**, so both read MISSING. Confirmed on disk:
  `build_target_source = 'UNDECLARED — no target stature was recorded for this build.'`
- `reissue()` already carries the field forward untouched (it starts from
  `p = dict(entry['params'])`); its docstring lists `height_target_m` among the inputs a
  re-issue must not edit. **No fix needed there.**

So the plumbing was never broken. What was missing is any way to *add* a declaration to an
already-issued body — a body derived before anyone thought to pass the argument could
never run a blocking Tier-1 gate, permanently.

**Built:** `reissue(..., set_target=...)`, CLI `--set-target name=METRES,...`, mirroring
the `set_anatomy` pattern already established for the other declared input. It writes
`height_target_m` **and** `character_spec['build_target_stature_mm']` (the two fields
`gates.Subject.from_registry` and `_anthro_spec` read separately — setting one and not the
other is how a body ends up declaring two different targets), stamps `build_target_source`
with who declared it, and appends to `height_target_changed` with the previous value.

Three-state contract on the field, mirroring the one `hand_correction` keeps:

| state | behaviour |
|---|---|
| recorded already | carried forward untouched — a re-issue edits no input |
| declared here | recorded, with its previous value and provenance |
| neither | stays **ABSENT**; the gate goes on reporting MISSING |

**It is never invented, and deliberately not derived from the delivered stature** — that
would make the gate pass by construction on every body forever and measure nothing. A body
issued before the field existed keeps reproducing its own cage hash either way: the field
is metadata and no vertex depends on it. Two guards refuse the ways a declaration lands on
the wrong character (both exercised below).
