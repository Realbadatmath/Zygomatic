Read `README.md` first. Plan section 2, section 7 Phase 1. Notes: `research_video_identity.md` sections 1, 2, 3; `research_process.md` Q1.

## Why this session exists
The leading open identity-through-video model, Wan2.2-Animate-14B, takes a reference image plus a proportion-correct per-frame 2D skeleton and face crops; its authors chose a 2D skeleton over a body model "for better generality, particularly for non-humanoid characters". Licence: Apache-2.0 on the HF card `Wan-AI/Wan2.2-Animate-14B` and the Wan2.2 README (verified 2026-09-02). ComfyUI supports it natively (`docs.comfy.org/tutorials/video/wan/wan2-2-animate`, node `WanAnimateToVideo`, modes "Move" = animate and "Mix" = replace). No weights are on disk (`diffusion_models` holds Wan2.1 I2V, T2V, VACE and Wan2.2 I2V A14B only). There is NO official Wan2.2 VACE; `alibaba-pai/Wan2.2-VACE-Fun-A14B` (Apache-2.0 on its card) is the 2.2-backbone route for depth plates. Traps recorded at source: the tutorial's preprocessing uses DWPose (banned, dataset non-commercial); the official `--use_flux` retarget uses FLUX.1-Kontext-dev (non-commercial); the authors do not recommend LoRAs trained on Wan2.2; face identity drifts at 81-frame chunk seams; the skeleton is human wholebody, so creatures need the VACE-Fun depth route instead.

   GATE: (ii) beats (i) and (iii); the seam drift is reported as a number, not a claim.
4. **LoRA compatibility.** Run (ii) with and without the Wan2.1 character LoRA (`wan_chars/wan_char_<id>.safetensors`) and record the identity delta and any artefacts by eye. State whether our Wan2.1 LoRAs survive on the Animate backbone.
