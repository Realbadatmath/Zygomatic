Date: 2026-09-02. Labels: VERIFIED-AT-SOURCE (read the page today), CLAIMED (secondary/aggregator or memory), ASSUMED (my inference), MEASURED (none in this phase — nothing was run).
Tool budget: 41 calls incl. this write. Fetch failures: LTX-2 LICENSE.md (404, resolved via /LICENSE), UniAnimate-DiT LICENSE (404 = no licence file at that path), Rokoko Vision ToS (403), Go-with-the-Flow repo (empty at Eyeline-Research URL).

## 0. The defect this dimension must close
FACTS: char_vace.py paints ONE STATIC skeleton; wan_vace_service.py fills grey-127 under the character mask; no per-shot pose tracks exist. Consequence: the video model re-invents the body every frame ("model reinvents what the constant hides"). Anything below is judged on ONE question: does it replace the constant with a per-frame, geometry-derived signal that the model cannot override, and is it licence-clean for a monetised EU channel.

## 1. Wan2.2-Animate-14B — VERIFIED-AT-SOURCE (HF card + Wan-Video/Wan2.2 README + preprocess/UserGuider.md, read 2026-09-02)
- Licence: "The models in this repository are licensed under the Apache 2.0 License" (github.com/Wan-Video/Wan2.2 README; HF card metadata license: apache-2.0, LICENSE.txt in repo). Code Apache-2.0. Released 2025-09-19.
- Modes: animation ("generates a video of the character image that mimics the human motion in the input video") and replacement ("replaces the character image with the input video" = puts our character INTO the driver footage, keeping driver background/lighting).
- Inputs after preprocessing: src_ref.png (reference), src_pose.mp4 (2D skeleton video), src_face.mp4 (driver face-crop sequence); replacement mode adds src_bg.mp4 + src_mask.mp4. Preprocessing stack: vitpose_h_wholebody.onnx (ViTPose-H wholebody 2D), yolov10m.onnx (person det), sam2_hiera_large.pt (mask), optional FLUX.1-Kontext-dev for `--use_flux` pose retargeting (WARNING: FLUX.1-Kontext-dev is non-commercial — do NOT enable; we can retarget by rendering our own reference from Anny). `--retarget_flag` expects "both the reference character and the character in the first frame of the driving video are in a front-facing, stretched pose". Replacement mask extraction is "designed for single-person videos ONLY".
- Official caveat: "If you're using Wan-Animate, we do not recommend using LoRA models trained on Wan2.2, since weight changes during training may lead to unexpected behavior." (Our 2 Wan char LoRAs: base unknown in FACTS — ASSUMED Wan2.1-trained; compatibility must be MEASURED, not assumed.)
- VRAM: the official efficiency table is an image; numbers not machine-readable (fetch returned "~35-40 GB A100 class for 14B" as a paraphrase — treat as CLAIMED). CLAIMED (community, 2025-10..2026): fp8-scaled KJ file runs 720p in ~20-24 GB with WanVideoWrapper; bf16 ~40 GB. Our 48 GB fits either. Disk: bf16 ≈ 28-33 GB + fp8 ≈ 15 GB against 139 GB free — tight, pick one.
- ComfyUI: NATIVE support VERIFIED (docs.comfy.org/tutorials/video/wan/wan2-2-animate): node "WanAnimateToVideo"; files Wan2_2-Animate-14B_fp8_e4m3fn_scaled_KJ.safetensors or wan2.2_animate_14B_bf16.safetensors; wan_2.1_vae, umt5_xxl fp8, clip_vision_h, lightx2v_I2V_14B_480p_cfg_step_distill_rank64 (4-step); modes named "Mix" (replace) and "Move" (animate). The documented preprocessing uses DWPose Estimator (controlnet_aux) — DWPose is BANNED in our policy (dataset NC). Substitute: paint the skeleton video ourselves from the fitted Anny (OpenPose-18/wholebody colour convention) or run the Apache ViTPose ONNX the official repo ships (ViTPose code Apache-2.0 CLAIMED; wholebody weights trained on COCO-WholeBody, academic dataset — ASSUMED tool-only risk, acceptable under operator policy since it never touches the output asset). WanVideoWrapper also has Animate nodes (CLAIMED, kijai issue #1262 2025-09).
- Identity failure modes (CLAIMED, community + paper reading; none measured here): (a) face identity comes from the reference, expression from src_face crops — long sequences chunked at 81 frames drift at chunk seams; (b) relighting LoRA (replacement mode) shifts skin tone/hair colour to match driver lighting; (c) skeleton is HUMAN wholebody — creatures with non-human body plans have no skeleton channel (pufferball is out of scope for Animate; use VACE-Fun depth instead); (d) body-proportion mismatch reference vs driver (Abel 12y driven by an adult) produces limb-length compromise unless retargeted — our Anny fit can render a proportion-correct skeleton from the driver's joint ANGLES, which is exactly the retarget the official `--use_flux` path tries to do with an NC image editor.
- How it closes the defect: every frame gets a skeleton + a face crop; nothing is constant, nothing is grey-127.
- Null model for any identity claim: per-frame AuraFace cosine to canon, reported against (i) the current static-skeleton VACE render of the same shot (do-nothing control), (ii) a wrong-reference run (another character's ref, same driver) to prove the metric discriminates, (iii) frame-shuffled score. A single "0.71 average" means nothing without (i)-(iii).

## 5. Pose tracks without SMPL
- SAM 3D Body (already live in body_venv, SAM License, 1.2 s/image): per-frame is the primitive. Temporal versions — VERIFIED (arXiv): SAM-Body4D 2512.08406 (Dec 2025, "training-free 4D human body mesh recovery from videos" built on SAM 3D Body) and 2512.21573 "World-Coordinate Human Motion Retargeting via SAM 3D Body" (locks shape/scale by averaging across the track; sliding-window optimisation in the MHR latent). Code availability of either: NOT verified (CLAIMED unknown). The recipe is reproducible in-house: SAM3 track -> SAM 3D Body per frame -> lock shape by median over track -> smooth joint rotations (one-euro/Savitzky) -> map MHR joint rotations to Anny pose params (SOMA-X hub is on disk) -> anny_animate renders per-frame skeleton+depth plates. This is THE missing "per-shot pose track".
  Null model: reprojection px error of the track vs RTMPose 2D per frame, reported against a held-first-frame null and the existing two-pose lerp null; a track that does not beat the lerp is not a track.
- MotionBERT — VERIFIED: Apache-2.0 (repo), 2D keypoints -> H36M-17 3D lifting (39.2 mm MPJPE); the mesh branch is SMPL (CLAIMED) and must not be used. Role: second, independent 3D lifter to cross-check SAM 3D Body joint angles (disagreement gate). Checkpoints trained on Human3.6M (academic dataset — ASSUMED tool-only risk).
- RTMPose/ViTPose 2D + anny_fit: already ours; the ViTPose-H wholebody ONNX shipped by Wan-Animate is a drop-in 2D source (Apache code — CLAIMED).
- FreeMoCap — CLAIMED (search, GitHub): AGPL tool (fine), multi-webcam, BVH/CSV/HDF5 export, MediaPipe-based. Requires a real performer + cameras. Rejected for driver-CLIP tracking; note as a capture option if the operator performs.
- Rokoko Vision — CLAIMED (aggregators; official ToS 403 today): free single-camera <= 15 s, FBX export on free tier, commercial use of exports allowed; BVH/streaming paid. Cloud upload. Rejected: ToS unverified, 15 s cap, cloud.
- Cascadeur — VERIFIED (cascadeur.com/plans): Free "Only non-commercial use", ".casc format only"; Indie "€16 per month" or "€7 per month billed annually" (= €84/yr), revenue "< $100k per year", exports .fbx/.dae/USD/glTF; "Every purchased Yearly Indie ... provides access to Perpetual license builds". Video-to-mocap not on the plans page (CLAIMED feature since 2024). Fits the 150 EUR cap and is perpetual after a year — the only defensible purchase in this dimension, and only if the in-house SAM3DB track proves too noisy to clean by hand.
- Mixamo — CLAIMED (Adobe FAQ): free, royalty-free commercial use of characters + animations; no redistribution of raw files. FBX motion library, not tracking. Useful as canned motion -> Anny -> plates.
